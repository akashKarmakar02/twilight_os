# Development Notes

## Build and verification

Run `make kernel` after kernel changes and `make userspace` after userspace
changes. Build the ISO with `make` before guest testing. Relevant checks are
`make test-tty`, `make test-time`, and `make test-net`; disk and Wayland changes
also require guest probes. See [AGENTS.md](../AGENTS.md) for verification rules
and [build-system.md](build-system.md) for prerequisites, including Snes9x.

## Updating the root filesystem

Edit base files beneath `rootfs/`, then run `make system-image` or rebuild the
ISO. `rootfs/bin` and `rootfs/sbin` are generated by `make userspace`.
`make initramfs` rebuilds the bootstrap payload (`init`, `oksh`, and `install`);
it does not pack the entire rootfs. `make cpio` is not a current target.

## QEMU networking and host files

The normal x86_64 and `run-blk-bios` recipes use QEMU user networking. With its
default subnet, a guest reaches host services at `10.0.2.2`. The rule
`hostfwd=tcp::8000-:80` works in the other direction: host port 8000 connects to
the guest HTTP server on port 80. It does not start a host file server on port
8080. `make run-bios` does not configure a NIC; use a network-enabled recipe
for transfers.

To serve a host directory containing development files, run there on the host:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Then, from a writable directory inside Twilight:

```sh
curl http://10.0.2.2:8080/example.txt -o example.txt
```

Use `10.0.2.2`, not `10.0.0.2`. For a connection timeout, check the IP, QEMU
network recipe, host server, and host firewall. A missing file normally
produces an HTTP response rather than a TCP connection timeout. See QEMU's
[default network topology](https://www.qemu.org/docs/master/system/devices/net.html).

## QEMU control and evidence

Several targets log to `qemu.log`; search it with `rg` rather than reading the
potentially large file whole. For headless tests, add a Unix monitor socket
and capture screenshots with `screendump /tmp/screen.ppm`. `sendkey` exercises
the keyboard path. TTY rendering bugs need framebuffer evidence as well as
serial logs; see [console.md](console.md#verification).

Leave serial-stdio QEMU with `Ctrl-A x`. Stop test VMs when finished. The
network harness uses a snapshot disk; the timing harness attaches no data disk.

## Generated files

Build outputs, caches, local `.ipk` packages, and game data stay out of commits.
Some rootfs runtime libraries remain tracked; inspect their rebuilds separately
from source changes. Avoid `git clean -fdx`: ignored disks and local test
assets may contain work you want to retain.
